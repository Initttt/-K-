# 我的装备

一个单用户、本地优先的个人电子设备价值管理应用。记录手机、平板、笔记本电脑、显卡的购买信息，查看来源明确的参考估值、估值变化、估算持有成本和历史快照。

**当前没有云同步，也没有接入真实行情平台。** 设备数据保存在当前浏览器中；清除浏览器数据、换浏览器或换访问地址都可能导致看不到原记录，请定期导出 JSON 备份。演示空间使用固定样例，始终与个人设备隔离。

## 安装与启动

技术栈：Next.js 16、React 19、TypeScript、Tailwind CSS 4、Lucide 图标；图表由项目中的 SVG 组件绘制。

建议使用 Node.js 22 LTS（至少 22.12）和 npm。所有命令都在本项目目录执行：

```bash
cd "/Users/zzzz/桌面宠物/电子设备K线"
npm ci --ignore-scripts
npm run dev
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。不需要密钥或账户即可使用设备管理、手动估值、演示和备份。

生产构建与启动：

```bash
npm run build
npm run start
```

默认只监听本机 `127.0.0.1`，不公开部署、不上传设备记录。开发和生产服务不能同时占用同一端口；需要其他端口时使用 `npm run dev -- --port 3001`。请固定浏览器和访问地址，`localhost`、`127.0.0.1`、不同端口的数据空间各自独立。

需要手机在同一可信 Wi-Fi 中体验时，先完成构建，再运行 `npm run start -- --hostname 0.0.0.0`，用手机打开 `http://电脑局域网IP:3000`。此选项会让同一网络的其他设备也能访问应用，请保持 AI 关闭、不要配置公网转发，用完按 Ctrl+C 停止。手机与电脑各自保存独立数据，可用 JSON 转移。本次验收使用真实 Chrome 的手机尺寸视口，未实测实体手机或 Safari。

依赖由 `package-lock.json` 固定，安装时禁用安装脚本。首次生成锁文件曾遇到 npm 10 的依赖解析错误，已通过项目内工具处理，并实际验证系统 npm 10 能运行上述 `npm ci --ignore-scripts`；无需修改全局 npm。详细来源与许可见 [docs/references.md](docs/references.md)。

## 五分钟体验流程

1. 首次进入“我的设备”是空账户。点击“先体验演示”或“演示空间”，查看五件样例、四件有估值的覆盖范围，以及显卡的“估值上升”。
2. 打开任意设备，查看购买信息、参考区间、来源、地区、币种、价格类型、数据日期和快照曲线。备用手机没有模拟估值，会显示“暂无估值”。
3. 点击“刷新估值”。固定模拟数据没有更新时，价格、数据日期和历史条数保持不变。
4. 切回“我的设备”，点击“添加设备”，填写名称、类别、品牌、型号、配置、购买日期和购买价格。成色、电池、标签、备注可以不填；显卡不显示电池字段。配置不确定时可以写“待补充”。
5. 保存后刷新网页，设备仍在。打开详情，点击“填写参考估值”，填写单一金额或区间、来源说明和数据日期；保存后产生一个真实保存的快照点。再次填写较新日期的参考值，就能查看历史变化。
6. 编辑设备名称或备注，验证信息更新；删除设备需要确认，同时删除其估值记录。修改品牌、型号、类别或配置时，如果已有估值，会另行确认清除旧估值，避免旧配置价格误用于新设备。
7. 进入“数据与备份”，导出 JSON。导入同一空间和市场的备份后先查看记录数量，再点击“确认替换当前记录”恢复；导入会覆盖当前空间，操作前先备份。
8. 打开“一句话录入”，未配置 AI 时可看到明确提示，并通过“继续手动填写”完成录入。

## 数据保存与市场隔离

本地存储位于浏览器的 `localStorage`，不是项目目录中的数据库文件。每个地区、币种、空间独立保存：

```text
my-gear:v1:personal:CN:CNY
my-gear:v1:personal:HK:HKD
my-gear:v1:personal:US:USD
my-gear:v1:demo:CN:CNY
```

默认简体中文、中国大陆、人民币。在“数据与备份”中可切换个人账户的中国香港 / 港币、美国 / 美元市场。切换市场不会换算汇率，不会改写旧记录的币种，也不会合并不同市场的价格。演示空间固定使用中国大陆 / CNY。

默认语言与市场列表在 `src/lib/config.ts`，本版界面文案为简体中文；修改为另一种语言还需要翻译界面文案。当前市场和空间偏好保存于 `my-gear:preferences:v1`，刷新后保持选择；其他市场的记录也独立保留。

同一浏览器的多个标签页会监听存储变化。存储被禁用、额度不足或记录无法解析时，会显示错误；无法读取已有记录时暂停覆盖，并提供原始数据导出入口。这不是多人协作数据库，不提供跨设备同步、并发冲突合并或服务端备份。

JSON 只导出当前空间与市场，包含设备和估值快照。导入会校验结构、字段、金额、日期、关联关系、地区、币种以及个人 / 演示标记；演示快照不能导入个人空间。界面限制单个备份文件不超过 5 MB。备份含设备及备注信息，请自行妥善保存。

## 估值与计算口径

估值不是已经实现的支出或收益，也不是保证可以卖出的价格。第一版提供两种数据源：

- **手动参考估值**：用户填写金额或上下限、来源说明、数据日期。始终显示为手动参考，不把用户输入当作已验证的成交价。
- **固定模拟行情**：仅用于演示空间，有确定的型号和配置映射。无匹配或证据不足时显示“暂无估值”，不猜价格。数据不随刷新随机变化。

每条快照保存 `source`、`region`、`currency`、`priceType`、`dataDate`、`recordedAt` 和估值区间。数据模型分别支持手动参考、模拟、挂牌、成交、回收报价；后三种类型是未来真实数据接入的预留结构，**当前没有对应真实数据源**。

当前参考值选择同一设备、同一地区与币种的最新有效快照；同一天多个快照按记录时间取最新。购买前或未来日期的快照不用于当前估值。区间统一使用中值 `(下限 + 上限) / 2` 参与计算，界面明确说明。

```text
价值变化 = 当前参考中值 − 买入价
价值变化率 = 价值变化 ÷ 买入价
日均估算持有成本 =（买入价 − 当前参考中值）÷ 持有天数
```

- 持有天数按购买日至今天的自然日差计算；当天购买按 1 天处理，避免除以零。
- 买入价可以为 0；其变化金额仍可计算，变化率不计算，显示“不适用”或空值并说明原因。
- 未来购买日期不能保存。无效日期、非法金额、上下限倒置均有校验。
- 缺少估值时，当前参考值、价值变化及日均成本显示为空，不按零元处理。
- 购入总金额包括当前账户全部设备。参考总值只汇总有估值设备；总价值变化及变化率仅与**同一组已估值设备**的购入金额比较。
- 升值显示“估值上升”；日均成本可能为负，只表示估值变化，不表示已经赚到钱。
- 日均成本不包含未记录的维修费、手续费等费用，不是已实现的消费或收入。

快照的数据日期距离今天**超过七天**时提示过期。第一版只有用户主动刷新，没有后台调度或“每周自动抓取行情”。手动估值刷新会提示填写新的参考值；未取得新数据时不会创建新快照，也不会把旧数据日期更新为今天。

历史曲线只连接保存过的快照。没有记录时显示空状态，只有一条时显示单个点，不补造缺失日期。图下同时提供记录信息；演示曲线明确标注“演示数据，非真实行情”。

## 演示数据说明

首次进入演示空间时，初始化五件固定样例：iPhone 16 Pro、MacBook Pro 14、iPad Air 11、GeForce RTX 4090、Pixel 8a。前四件有 2026 年 6 月至 11 月的模拟快照，显卡演示估值上升；Pixel 8a 故意不提供模拟估值，以展示缺少数据的处理方式。

这些价格、时间序列和区间均为人工编写的演示值，不代表真实挂牌、成交或回收行情。样例不是市场预测，不包含伪造的样本量或置信度。演示空间中的新增、编辑、删除、手动估值和备份同样有效，只保存在独立演示账本中，不进入个人统计。

## 可选 AI：用一句话添加设备

AI 默认关闭，完整的手动流程不依赖 AI。配置方式：

```bash
cp .env.example .env.local
```

在项目内 `.env.local` 中填写：

```dotenv
AI_ENABLED=true
OPENAI_API_KEY=你自己授权使用的服务端密钥
OPENAI_MODEL=你有权限使用且支持结构化输出的模型标识
```

然后重启服务。三个条件均满足才显示已配置。应用不预选模型，也不会读取其他项目的密钥；请自行确认对应服务的价格、额度和授权后再启用。`.env.local` 已被忽略，不应提交；禁止给密钥变量加 `NEXT_PUBLIC_` 前缀或放入浏览器存储。

仅在用户主动点击提取时，输入文字才由服务端发往 OpenAI Responses API，使用严格 JSON Schema 和 `store: false`。结果只预填表单，用户检查并确认后才保存。没有提到的字段留空；例如只提供“2026 年 5 月”时不会补猜具体日，需要用户补全。AI 不产生市场估值。模型仍可能误提取，所以人工检查不可省略。

没有配置时明确显示“AI 尚未配置”，可继续手动录入；没有用规则识别或模拟结果伪装真实 AI。网络失败、拒绝、限流、超时或无效输出都有错误处理。测试使用 mock，不产生费用；**未使用真实账户或密钥验证模型连通性**。

实现、已查阅的官方文档和限制见 [docs/ai.md](docs/ai.md)。该接口目前适用于本地单用户运行，没有公网所需的登录、限流和账单控制，不能将本地版本直接视为可公开运营的服务。

```bash

npm run test:e2e
```

单元测试位于 `tests/`，覆盖计算边界、缺失估值、零买入价、日期、市场及空间隔离、备份校验、稳定模拟刷新，以及 AI 的配置状态、结构化输出和错误处理。AI 测试全部使用模拟网络响应，验证接口逻辑，不代表已验证真实模型服务。

浏览器测试使用本机 Google Chrome，无需下载额外浏览器。若机器没有 Chrome，请先自行安装，或在 `playwright.config.ts` 中选择已有浏览器。测试自动启动本地服务，使用隔离的浏览器上下文，截图、临时浏览器资料和报告均在项目内。

实际验收（2026-11-08）：类型检查、ESLint、39 项单元/接口测试、生产构建均通过；5 条真实 Chrome 完整操作流程通过，覆盖增改删、重载保留、估值与缺失汇总、零价格、备份导入导出、模拟稳定及隔离、未来日期、市场切换、损坏数据保护、AI 未配置及 390 × 844 手机布局。AI 成功预填流程用模拟网络响应验证，未调用真实模型。最终浏览器测试运行在 `npm run start` 启动的生产版本上。详细记录与截图见 [docs/verification.md](docs/verification.md)。


接入真实行情时，在 `src/lib/valuation.ts` 实现新的 `ValuationProvider`，在服务端适配获授权的数据源，再接入刷新流程。必须保留来源、地区、币种、价格类型和真实数据日期，明确区分挂牌价、成交价、回收报价；请求失败或没有新数据时返回空结果，不伪造快照。设备型号和配置不匹配时应保持暂无估值。

接入云存储时，以 `src/lib/storage.ts` 为替换入口，并调整 `gear-app.tsx` 的加载与保存调用；增加真实身份验证、服务端校验、迁移和冲突处理后再考虑多设备同步。估值计算与设备模型不应绑定某一家数据库或模型服务。

## 当前完成与限制

已实现本地设备增删改查、类别筛选与搜索、可选标签和备注、单设备详情、手动参考区间和快照、固定模拟行情、估值覆盖与一致口径汇总、过期提示、JSON 备份和确认恢复、独立演示空间、响应式界面，以及可配置的服务端 AI 辅助录入。

本版不包含真实行情自动接入、后台定时刷新、云同步、注册登录、支付订阅、二手交易、社交、推送、原生客户端或复杂后台。未知型号不会自动估值；支持录入某一类设备不代表覆盖其全部型号。没有公开部署或创建远程仓库。
